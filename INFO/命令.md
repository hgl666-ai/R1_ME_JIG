0. 总览
--------------------------------------------------------------------------------

0.1 帧格式

 偏移   0    1          2            3             4            5           6          7        8 .. 8+L-1     8+L       9+L
         A5   5B   CMD_H  CMD_L  SEQ_H  SEQ_L  LEN_H  LEN_L   DATA...      CRC_H  CRC_L

    +--------+------+----------------------------------------------------------+
    | 字段   | 字节 | 说明                                                     |
    +--------+------+----------------------------------------------------------+
    | 帧头 F |  2   | 固定 A5 5B                                               |
    | 命令 C |  2   | 大端 u16，见第 1 章命令表                                |
    | 序号 N |  2   | 大端 u16，从 1 递增、FFFF 回卷；0 专供"主动帧"            |
    | 长度 L |  2   | 大端 u16，表示 DATA 的字节数（不含帧头/CRC）             |
    | 数据 D |  L   | 见各命令说明                                             |
    | CRC16  |  2   | MODBUS 校验，大端存放                                    |
    +--------+------+----------------------------------------------------------+

    一帧最短 10 字节（L=0）。单帧 DATA 上限 256 字节（FRAME_MAX_DATA）。

0.2 字节序
    所有多字节字段大端（高字节在前）。

0.3 CRC16 规则
    算法    : MODBUS（多项式 0xA001 反射，初值 0xFFFF）
    计算范围: 从"帧头 A5"到"数据 D 的最后一个字节"（不含 CRC 自身）
    存放    : 大端（高字节在前）
    校验失败: 只做诊断、不回任何应答，直接丢弃整帧，发送方靠超时重发。
    实现    : U2/Core/Src/protocol_frame.c  Frame_CRC16()
    自检    : CRC16("123456789") = 0x4B37
              （主机侧回归测试 test_host/test_frame.c 每次构建都会校验这个向量）

0.4 帧序号 N 与 ACK 规则
    1) PC 每发一帧 N 递增（从 1 开始，0xFFFF 后回卷，跳过 0）。
    2) 应答帧的 N 等于请求帧的 N（ACK 回显）。
    3) 治具主动发起的帧（本固件暂无）N 一律为 0。
    4) ★ 当前固件**不校验** N：收到什么就原样回什么。
       也就是说 N 填 1、填 0xFFFF、甚至填 0，U2 都会正常处理并回显。
       调试时全程用 0x0001 最省事，也便于和应答比对。
    5) 命令码未定义 → 回 FF（NIY），不静默丢弃。

0.5 状态码总表（沿用 M1 协议 xlsx 的【通用状态码】表）
    +------+------------------+------------------------------------------------+
    | 码   | 名称             | 含义                                           |
    +------+------------------+------------------------------------------------+
    | 0x00 | OK               | 成功                                           |
    | 0x01 | BUSY             | 系统忙：电机正在运动时收到 MOTOR_MOVE          |
    | 0x02 | ERR_SIZE         | 文件大小异常                （本固件未使用）   |
    | 0x03 | ERR_FLASH        | SPI Flash 读写失败          （本固件未使用）   |
    | 0x04 | ERR_PROG         | ISP 烧录失败                （本固件未使用）   |
    | 0x05 | ERR_TEST         | 测试判定失败                （本固件未使用）   |
    | 0x06 | ERR_NO_FW        | 固件不存在                  （本固件未使用）   |
    | 0x07 | ERR_INCOMPLETE   | 固件不完整                  （本固件未使用）   |
    | 0x08 | ERR_CRC          | 帧 CRC 错误（仅诊断，不回 ACK）                |
    | 0x09 | ERR_SEQ          | 帧序号非递增（仅警告，不拒绝；本固件未实现）   |
    | 0x0A | ERR_COUNT        | 上传字节数与声明不符        （本固件未使用）   |
    | 0x0B | ERR_PARAM        | 参数错误（长度不对 / 方向非法 / 步数为 0）     |
    | 0x0C | ERR_TIMEOUT      | 超时                        （本固件未使用）   |
    | 0x0D | ERR_OVERFLOW     | 溢出                        （本固件未使用）   |
    | 0xFF | NIY              | 命令未实现                                     |
    +------+------------------+------------------------------------------------+
    注：0x02~0x07、0x0A、0x0C、0x0D 在本固件里不会产生，保留编号是为了和
        M1 治具协议保持同一张表，PC 端可以共用一套错误码解析代码。

0.6 命令总表
    +--------+--------------------------------+--------+--------+--------+
    | 命令   | 功能                           | 方向   | 请求LEN| 应答LEN|
    +--------+--------------------------------+--------+--------+--------+
    | 0x0001 | PING 连通性测试                | PC→U2  |   0    |   1    |
    | 0x0002 | 查询固件版本号                 | PC→U2  |   0    |   4    |
    | 0x0010 | 电机定长运动（带梯形加减速）   | PC→U2  |   7    |   1    |
    | 0x0011 | 电机立即停止                   | PC→U2  |   0    |   1    |
    | 0x0012 | 查询电机运动状态               | PC→U2  |   0    |  10    |
    | 0x0020 | 查询 MRE 采样窗口              | PC→U2  |   0    |  22    |
    | 0x0021 | U2/U3 交叉校验                 | PC→U2  |   0    |  44    |
    | 0x0022 | MRE 整圈极值（判上下限）        | PC→U2  |   1    |   9    |
    +--------+--------------------------------+--------+--------+--------+
    条数口径：全部为 PC 请求/应答命令，共 8 条。本固件**没有**主动上报帧，
    也没有 U2↔U3 的内部链路协议（U3 未启用）。

0.7 与 M1/FOC 治具协议的关系
    相同：帧头、字段顺序、大端、CRC16 算法、状态码表、N 回显规则。
    不同：
      1) M1 的命令码（0x0009~0x0112）在本固件里**全部未实现**，发过去一律回
         0xFF NIY。本固件只用 0x0001/0x0002/0x0010~0x0012/0x0020/0x0021/0x0022。
      2) M1 是 U1 主控 + U2 测量副控双芯片；R1 这块板虽然也有 U2/U3 两颗
         F103RCT6，但**只有 U2 接了 USB**，U3 在固件里完全没启用。
      3) M1 的波特率 460800 是实体 UART 参数；R1 走 USB CDC，波特率是名义值，
         PC 端设多少都不影响实际速率。

1.1  0x0001  PING 连通性测试
--------------------------------------------------------------------------------
功能      : 确认治具在线、协议层正常工作。这是上板后第一个该发的命令。
发送方    : PC
接收方    : 治具 U2
帧头      : A5 5B
命令      : 00 01
帧序号    : N（递增）
数据长度  : 00 00
数据      : 无
CRC16     : 同上
ACK 内容  : 命令 00 01；帧序号 = N；长度 00 01（= 1）；
            数据 = [0] 状态码（恒为 00 OK）
示例      : N=1
            PC → : A5 5B 00 01 00 01 00 00 89 0C
            U2 → : A5 5B 00 01 00 01 00 01 00 95 88
备注      : 1) 收到应答说明 USB 接收中断、解帧、命令分发、USB 发送四条路都通。
            2) ★ PC13 指示灯亮**不能**证明固件在跑 —— PC13 在 MX_GPIO_Init()
               里就被拉低了，卡在 Error_Handler() 或 HardFault 里灯一样亮。
               所以 PING 才是真正的活体判据。

1.2  0x0002  查询固件版本号
--------------------------------------------------------------------------------
功能      : 读固件版本。用于确认烧进去的是不是当前这一版。
发送方    : PC
接收方    : 治具 U2
帧头      : A5 5B
命令      : 00 02
帧序号    : N（递增）
数据长度  : 00 00
数据      : 无
CRC16     : 同上
ACK 内容  : 命令 00 02；帧序号 = N；长度 00 04（= 4）；
            数据 = [0] 状态码（00 OK）
                   [1] 主版本号  PROTO_FW_MAJOR   = 0x01
                   [2] 次版本号  PROTO_FW_MINOR   = 0x00
                   [3] 修订号    PROTO_FW_PATCH   = 0x01
示例      : N=1
            PC → : A5 5B 00 02 00 01 00 00 89 48
            U2 → : A5 5B 00 02 00 01 00 04 00 01 00 01 8A A7
备注      : 版本号定义在 U2/Core/Inc/protocol.h 的 PROTO_FW_* 三个宏，改版本要
            同时改这三个宏并重新编译，否则查出来的还是旧号。

1.3  0x0010  电机定长运动
--------------------------------------------------------------------------------
功能      : 按指定方向、步数、巡航频率走一段定长行程。带梯形加减速。
发送方    : PC
接收方    : 治具 U2
帧头      : A5 5B
命令      : 00 10
帧序号    : N（递增）
数据长度  : 00 07
数据      : [0]     方向：00 = CW（DIR 引脚拉低）
                        01 = CCW（DIR 引脚拉高）
                        其它值 → 回 0B ERR_PARAM
            [1..4]  步数，大端 u32，有效范围 1 ~ 100000000
                    0 或超过上限 → 回 0B ERR_PARAM
            [5..6]  巡航步进频率 Hz，大端 u16
                    实际会被夹到 [300, 20000]；超出范围不报错，按边界值执行
            LEN != 7 → 回 0B ERR_PARAM
CRC16     : 同上
ACK 内容  : 命令 00 10；帧序号 = N；长度 00 01（= 1）；
            数据 = [0] 状态码：00 OK        已启动
                                01 BUSY      上一次还没走完
                                0B ERR_PARAM 长度/方向/步数不合法
示例      : 正转 3200 步（一圈）@4000Hz，N=1
            PC → : A5 5B 00 10 00 01 00 07 00 00 00 0C 80 0F A0 B3 A9
            U2 → : A5 5B 00 10 00 01 00 01 00 D4 8B
备注      : 1) **非阻塞**：立刻回 ACK，之后用 0x0012 查进度。
            2) 运动过程中再发 0x0010 一律回 01 BUSY。要打断先发 0x0011。
            3) 步数与转角的换算：16 微步 × 200 步/圈 = 3200 步/圈
               （电机 1.8°/步）。3200 步 = 1 圈，1600 步 = 半圈。
            4) 加减速：起步 500Hz，加减速段各最多 800 步；
               总步数不足 2×4 步时不做加减速，全程按目标频率跑。
               直接以目标频率硬启停会丢步，这是参考项目 U7 踩过的坑。
            5) ★ ACK 只代表"脉冲开始发了"，不代表轴真的在转。固件只能数自己
               发出的 STEP 脉冲，板上的编码器反馈没有接回 MCU。
            6) 实现：U2/Core/Src/bsp_motor.c  BSP_Motor_Move()

1.4  0x0011  电机立即停止
--------------------------------------------------------------------------------
功能      : 立刻停止 STEP 脉冲输出，未走完的步数作废。
发送方    : PC
接收方    : 治具 U2
帧头      : A5 5B
命令      : 00 11
帧序号    : N（递增）
数据长度  : 00 00
数据      : 无
CRC16     : 同上
ACK 内容  : 命令 00 11；帧序号 = N；长度 00 01（= 1）；
            数据 = [0] 状态码（恒为 00 OK）
示例      : N=1
            PC → : A5 5B 00 11 00 01 00 00 4A CD
            U2 → : A5 5B 00 11 00 01 00 01 00 05 8A
备注      : 1) 无论当前是否在运动都回 OK，可以当"清零/保险"用。

            3) 实现：U2/Core/Src/bsp_motor.c  BSP_Motor_Stop()

1.5  0x0012  查询电机运动状态
--------------------------------------------------------------------------------
功能      : 查当前是否在运动、走了多少步、目标多少步。
发送方    : PC
接收方    : 治具 U2
帧头      : A5 5B
命令      : 00 12
帧序号    : N（递增）
数据长度  : 00 00
数据      : 无
CRC16     : 同上
ACK 内容  : 命令 00 12；帧序号 = N；长度 00 0A（= 10）；
            数据 = [0]      状态码（恒为 00 OK）
                   [1]      运行标志：00 = 已停 / 01 = 正在运动
                   [2..5]   已走步数，大端 u32
                   [6..9]   目标步数，大端 u32
示例      : 刚上电（什么都没发过），N=1
            PC → : A5 5B 00 12 00 01 00 00 4A 89
            U2 → : A5 5B 00 12 00 01 00 0A | 00 00 | 00 00 00 00 | 00 00 00 00 | 7C B9
            走完 3200 步之后
            U2 → : A5 5B 00 12 00 01 00 0A | 00 00 | 00 00 0C 80 | 00 00 0C 80 | CE BC
备注      : 1) 目标步数是**最近一次** MOTOR_MOVE 的设定值；上电未发过命令时为 0。
            2) 运动结束时"已走步数"会等于"目标步数"（中断里补齐）。
            3) 实现：U2/Core/Src/bsp_motor.c  BSP_Motor_GetDone()/GetTarget()

--------------------------------------------------------------------------------
1.6  0x0020  查询 MRE 采样窗口
--------------------------------------------------------------------------------
功能      : 读最近一个采样窗口的 MRE 统计值，同时反映 ADC 与 TMC2209 的健康状态。
发送方    : PC
接收方    : 治具 U2
帧头      : A5 5B
命令      : 00 20
帧序号    : N（递增）
数据长度  : 00 00
数据      : 无
CRC16     : 同上
ACK 内容  : 命令 00 20；帧序号 = N；长度 00 16（= 22）；
            数据 = [0]        状态码（恒为 00 OK）
                   [1]        flags，见下表
                   [2..3]     mre_last   最近一次原始值（12 位，0~4095）
                   [4..5]     mre_min    本窗口内最小值
                   [6..7]     mre_max    本窗口内最大值
                   [8..9]     mre_mean   本窗口内平均值
                   [10..11]   mre_mv     mre_last 换算成 mV
                   [12..13]   vref_last  3V3_ADC0 通道原始值（理论 ≈2047）
                   [14..15]   vref_mv    同上换算成 mV（理论 ≈1650）
                   [16..17]   window_size 本窗口样本数（固定 0x0100 = 256）
                   [18..21]   total_samples 上电以来累计 MRE 样本数，大端 u32
示例      : 实机采集，N=1（数据取自 2026-11-06 上板记录）
            PC → : A5 5B 00 20 00 01 00 00 8E B0
            U2 → : A5 5B 00 20 00 01 00 16 00 03 0A 3B 0A 37 0A 3D 0A 3A 08 3E 07 FB 06 6E 01 00 00 16 83 00 14 20
            上面这一帧按数据段 D 逐字节拆开就是：
                   [0]      00                 状态码 OK
                   [1]      03                 flags=0x03（ADC 在跑 + TMC 就绪）
                   [2..3]   0A 3B              mre_last  = 2619
                   [4..5]   0A 37              mre_min   = 2615
                   [6..7]   0A 3D              mre_max   = 2621
                   [8..9]   0A 3A              mre_mean  = 2618
                   [10..11] 08 3E              mre_mv    = 2110 mV
                   [12..13] 07 FB              vref_last = 2043
                   [14..15] 06 6E              vref_mv   = 1646 mV
                   [16..17] 01 00              window_size = 256
                   [18..21] 00 16 83 00        total_samples = 1475328
                   最后 2 字节 14 20 为 CRC16
备注      : 1) flags 位定义：
                  bit0 = ADC/DMA 正在连续采集
                  bit1 = TMC2209 配置写入并读回校验通过
                  → 0x03 表示两项都正常；0x01 表示 ADC 正常但 TMC 没配上
                    （电机可能仍能转，但微步/电流不确定）。
            2) 采样参数：ADC 时钟 12MHz、采样时间 239.5 周期，
               每通道约 **23.8 kSa/s**；一个窗口 256 点 ≈ **10.7 ms**，
               统计值每 10.7 ms 刷新一次。
            3) total_samples 每秒约涨 23800。连发两次如果它不涨，说明 DMA
               没有在搬数据。它**只增不减**，倒退 = 板子复位过。
            4) vref 通道用于交叉校验 3.3V 基准：VDDA = vref_mv × 4095 / vref_raw
               （理论上 3V3_ADC0 = 3.3V/2 = 1650mV）。用它可判断基准是否漂移。
            5) ★ mre_mv 的绝对精度取决于 VDDA 是否为 3.300V（固件里硬编码
               ADC_VDDA_MV=3300）。VDDA 有偏差时用第 4 条反推修正。
            6) ★ mre_mv 反映的是 U7(LM358) 跟随器的输出。若输入超出运放共模
               范围会被削顶，此时数值不代表真实输入电压
               （定性判断与实测见 INFO/实现现状与验证记录.md）。
            7) 实现：U2/Core/Src/bsp_adc.c  BSP_ADC_GetSnapshot()
                     U2/Core/Src/protocol.c  case PROTO_CMD_MRE_QUERY

1.7  0x0021  U2/U3 交叉校验
--------------------------------------------------------------------------------
功能      : 同时取 U2 和 U3 的 MRE 采样快照并比对, 判断两片测量链路是否一致。
发送方    : PC
接收方    : 治具 U2（U2 再通过内部链路去问 U3, 见第二章）
帧头      : A5 5B
命令      : 00 21
帧序号    : N（递增）
数据长度  : 00 00
数据      : 无
CRC16     : 同上
ACK 内容  : 命令 00 21；帧序号 = N；长度 00 2C（= 44）；
            数据 = [0]      状态码：00 OK / 05 ERR_TEST（超差）/ 0C ERR_TIMEOUT（U3 无应答）
                   [1]      peer_flags：bit0 U3 有合法应答
                                       bit1 U3 的 ADC 在采集
                                       bit2 超出判据（存在超差）
                   [2..22]  U2 快照 21B（布局同 1.6 的 D[1..21]）
                   [23..43] U3 快照 21B（同上；U3 无应答时全 0）
示例      : N=1（取 2026-11-06 的实机快照，并假设 U3 与 U2 一致）
            PC → : A5 5B 00 21 00 01 00 00 4E 8D
            U2 → : A5 5B 00 21 00 01 00 2C 00 03 03 0A 3B 0A 37 0A 3D 0A 3A 08 3E 07 FB 06 6E 01 00 00 16 83 00 03 0A 3B 0A 37 0A 3D 0A 3A 08 3E 07 FB 06 6E 01 00 00 16 83 00 B0 D2
备注      : 1) 判据在 U2/Core/Inc/protocol.h 里：
                  |mre_last  差| > 50 LSB（≈40mV） 或
                  |vref_last 差| > 20 LSB
                  → 判超差, 状态码回 05, peer_flags 的 bit2 置 1。
            2) ★ 两路缓冲接的是**同一个输入节点**（MRE 走 U7 的两个半边，
               TBS 走 U6 的两个半边），所以这个比对检查的是"两条测量链路的
               一致性"，不是两个不同的物理量。它能发现某一片的 ADC / VDDA /
               运放出问题，发现不了信号本身的问题。
            3) U3 不在线时本命令阻塞约 60ms（2 次重试 × 2 段超时）。期间
               USB 接收中断照常工作，不会丢帧。
            4) 链路要求 H3 排针插 1-2、3-4 两个短接帽。
            5) 实现：U2/Core/Src/link_u3.c  LINK_Command()
                     U2/Core/Src/protocol.c  case PROTO_CMD_CROSS_CHECK

--------------------------------------------------------------------------------
1.8  0x0022  MRE 整圈极值
--------------------------------------------------------------------------------
功能      : 取"自上次清零以来"累计的 MRE 最低/最高值, 用于判整圈有没有超出上下限。
发送方    : PC
接收方    : 治具 U2
帧头      : A5 5B
命令      : 00 22
帧序号    : N（递增）
数据长度  : 00 01 或 00 07
数据      : [0] 模式：00 = 只读
                        01 = 读并清零（返回的是清零前的值）
                        02 = ★自动测一圈：清零 → 正转一圈 → 读结果
            模式 00/01 时 LEN 必须 = 1。
            模式 02 时 LEN 可以是 1（用默认 3200 步 @4000Hz）
                             也可以是 7：[0]模式 + [1..4]步数 + [5..6]频率
            其它模式 / 长度不对 → 回 0B ERR_PARAM
CRC16     : 同上
ACK 内容  : 命令 00 22；帧序号 = N；长度 00 09（= 9）；
            数据 = [0]     状态码：00 = 合格（或还没采到数据）
                                 05 = 超出上下限，不合格
                                 01 = 电机正忙（上一次还没走完）
                                 0B = 参数错误（模式/长度/步数非法）
                                 0C = 运动超时（没转完就停了）
                   [1..2]  整圈最低值 mre_peak_min（12 位原始值）
                   [3..4]  整圈最高值 mre_peak_max
                   [5..8]  累计样本数，大端 u32（0 表示清零后还没采到数据）
示例      : seq=1
            ★一条命令测一圈 PC → : A5 5B 00 22 00 01 00 01 02 07 0E
            合格时    U2 → : A5 5B 00 22 00 01 00 09 00 09 00 0B 80 00 0F 42 40 5A AE
                              （约 0.8 秒后才回，因为要等电机走完）
            不合格时  U2 → : A5 5B 00 22 00 01 00 09 05 08 00 0B 80 00 0F 42 40 C6 50
            只读      PC → : A5 5B 00 22 00 01 00 01 00 C6 8F
            清零      PC → : A5 5B 00 22 00 01 00 01 01 06 4E
备注      : 1) ★ MRE_ADC 是随角度变化的量，不是恒值。所以判的是**整圈转下来
               出现过的最低值和最高值**，不是某一瞬间的读数 —— 瞬时值转到某些
               角度必然低、某些必然高，拿它判永远不会合格。
            2) 判据（U2/Core/Inc/protocol.h，占位值，必须按 DUT 改）：
                  peak_min < PROTO_MRE_PEAK_LO (默认 200, ≈161mV)  或
                  peak_max > PROTO_MRE_PEAK_HI (默认 3900, ≈3143mV)
                  → 状态码回 05
               也可以忽略固件的状态码，PC 端自己拿 [1..4] 两个值比。
            3) 典型用法（只要一条命令）：
                 发 mode=02 → 固件自己清零、转一圈、等走完、读极值、判合格，
                 一次返回结果。默认 3200 步 @4000Hz（约 0.8 秒）。
                 要换圈数/速度就发 LEN=7 的版本：
                   数据 = 02 | 步数(4, 大端) | 频率(2, 大端)
                 需要手动分步时才用 mode=00/01。
            4) 极值跨窗口累计，每 10.75ms 并入一次，所以转一圈的一万个样本
               (6.4 秒) 全部覆盖，不会漏掉峰值。
            5) 实现：U2/Core/Src/bsp_adc.c  BSP_ADC_GetPeak()
                     U2/Core/Src/protocol.c  case PROTO_CMD_MRE_PEAK

================================================================================
二、U2 ↔ U3 内部链路
================================================================================

用途      : U2 作主机, 通过 USART1 向 U3 取测量快照做交叉校验。
            PC 端不直接访问这条链路, 它只在 0x0021 内部被调用。
物理层    : USART1, PA9=TX / PA10=RX, 115200 8N1。
            H3 排针必须插 1-2 与 3-4 两个短接帽（TX↔RX 交叉相接），否则不通。
帧格式    : 与第一章**完全一致**（同一份 protocol_frame.c），命令码占 0x01xx 段。
线上契约  : 集中在 link_proto.h，U2 与 U3 各放一份完全相同的副本，改一边必须改另一边。
校验      : 主机侧每帧校验 帧头 / 长度 / CRC16 / 命令回显 / 序号回显，失败重试 2 次。

命令总表
    +--------+--------------------------------+--------+--------+--------+
    | 命令   | 功能                           | 方向   | 请求LEN| 应答LEN|
    +--------+--------------------------------+--------+--------+--------+
    | 0x0101 | PING（活体 + 版本 + 运行时长） | U2→U3  |   0    |   8    |
    | 0x0102 | 取 MRE 采样快照                | U2→U3  |   0    |  22    |
    +--------+--------------------------------+--------+--------+--------+

--------------------------------------------------------------------------------
2.1  0x0101  PING
--------------------------------------------------------------------------------
功能      : 确认 U3 在线, 并取它的固件版本与运行时长。
请求数据  : 无
ACK 内容  : 长度 00 08；
            数据 = [0]     状态码（00 OK）
                   [1..3]  主/次/修订版本（必须与 U2 的 LINK_FW_* 一致）
                   [4..7]  运行毫秒, 大端 u32
示例      : seq=1
            U2 → : A5 5B 01 01 00 01 00 00 58 0D
            U3 → : A5 5B 01 01 00 01 00 08 00 01 00 00 00 00 27 10 60 75
备注      : 版本不一致说明有一边没重新烧录, 交叉校验前应先查这一帧。

--------------------------------------------------------------------------------
2.2  0x0102  取 MRE 采样快照
--------------------------------------------------------------------------------
功能      : 取 U3 最近一个采样窗口的统计值。
请求数据  : 无
ACK 内容  : 长度 00 16（= 22）；
            数据 = [0]      状态码（00 OK）
                   [1..21] 快照 21B，布局与第一章 1.6 的 D[1..21] 完全相同：
                            flags(1) + mre_last(2) + mre_min(2) + mre_max(2) +
                            mre_mean(2) + mre_mv(2) + vref_last(2) + vref_mv(2) +
                            window_size(2) + total_samples(4)
示例      : seq=2
            U2 → : A5 5B 01 02 00 02 00 00 58 B9
            U3 → : A5 5B 01 02 00 02 00 16 00 03 0A 3B 0A 37 0A 3D 0A 3A 08 3E 07 FB 06 6E 01 00 00 16 83 00 85 DC
备注      : U3 的采样参数与 U2 完全相同（ADC 12MHz、239.5 周期、23.8 kSa/s、
            窗口 256 点 ≈10.7ms），因为两边是同一份 bsp_adc.c。
            两片的窗口并非严格同步，但 MRE 信号变化远慢于 10.7ms，按窗口比对足够。

附录 A  MRE 采样链参数
================================================================================
    ADC 时钟          : 12 MHz（PCLK2 72MHz ÷ 6）
    采样时间          : 239.5 周期
    单次转换          : (239.5 + 12.5) / 12MHz = 21 µs
    一次扫描（2 通道）: 42 µs
    每通道采样率      : 1/42µs ≈ 23.8 kSa/s
    窗口长度          : 256 点 = 10.7 ms
    DMA 缓冲          : 1024 半字（2 个窗口，双缓冲避免撕裂）
    转换序列          : rank1 = IN0 (PA0, MRE)
                        rank2 = IN4 (PA4, 3V3_ADC0)
    分辨率            : 12 位，1 LSB = 3300mV / 4095 ≈ 0.806 mV
    无抗混叠滤波      : 信号频率远低于 Nyquist（11.9 kHz），实际影响可忽略
